# Генератор карточек контрольно-измерительных приборов

Локальный прототип для контент-менеджера B2B-каталога. По ID товара программа получает исходные данные и формирует Markdown-черновик с SEO-заголовком, описанием, техническими характеристиками, поисковыми запросами и блоком для менеджера.

## Установка и запуск

Подготовьте окружение Python 3.11 и установите зависимости.

```console
python -m pip install pandas lxml
```

Установите и запустите Ollama. [Инструкция для Windows](https://docs.ollama.com/windows)

Загрузите модель `qwen3.5:9b`. [Страница модели](https://ollama.com/library/qwen3.5:9b)

```console
ollama pull qwen3.5:9b
```

Откройте терминал в корне проекта рядом с `generate_cards.py` и запустите скрипт.

```console
python generate_cards.py
```

Когда скрипт запросит ID, введите `58383, 189828` и нажмите Enter. ID можно разделять пробелами или запятыми. Пустой ввод запускает обработку уже записанной очереди из `data/ids.json`.

Сохранённые карточки появятся в `examples/`.

### Запуск через батник в Windows

Выполните команду из корня проекта в командной строке Windows.

```bat
run_generate_cards.bat
```

Батник использует `curl.exe` для проверки локального API. Если API недоступен, он пытается запустить Ollama через `ollama.exe serve`. После каждой обработки батник снова открывает ввод ID. Для выхода нажмите Ctrl+C или закройте окно консоли.

### Запуск в Jupyter

Откройте `AI - generate_cards.ipynb` в корне папке `notebook`. Выберите окружение, где установлены `pandas` и `lxml`, и запустите Ollama. Запишите в `data/ids.json` массив `[58383, 189828]` и выполните все ячейки сверху вниз.

## Входные данные и результаты

| Путь | Назначение |
| --- | --- |
| `generate_cards.py` | Консольный запуск генерации |
| `run_generate_cards.bat` | Запуск из командной строки Windows с проверкой Ollama |
| `AI - generate_cards.ipynb` | Блокнот с этапами подготовки и генерации |
| `data/product/product_<ID>.json` | Название, производитель, характеристики и исходное описание товара |
| `data/feed.xml` | XML-каталог со ссылками на страницы товаров для первой выгрузки |
| `data/ids.json` | Очередь ID товаров |
| `data/to_fix.json` | Причины ошибок и уточнения по ID |
| `examples/card_<ID>.md` | Сохранённые Markdown-карточки |
| `temp/` | Временные файлы при записи |

Файл товара содержит `name`, `manufacturer`, `description` и объект `specs` с парами «название характеристики - значение». Если готового JSON для ID ещё нет, скрипт ищет товар в `data/feed.xml`, извлекает описание и характеристики со страницы и сохраняет JSON для следующих запусков. Для такой выгрузки сохраните каталог как `data/feed.xml`. [XML-фид каталога](https://www.souz-pribor.ru/yml/any/feed.xml)

После записи отчёта из очереди удаляются ID сохранённых карточек и ID с записанными ошибками. Чтобы повторить обработку после исправления данных, снова введите нужный ID. Успешное сохранение карточки удалит прежнюю запись об ошибке для этого ID `to_fix.json` в папке `data`.

## Промпт и проверка ответа

1. Перед запросом программа проверяет структуру JSON товара и заполненность полей. Если данных не хватает, в отчёте указывается конкретное поле.
2. Системный промпт задаёт роль редактора B2B-каталога и просит опираться на исходное описание. Модель получает название, производителя и описание. Схема JSON задаёт поля ответа, а статус `insufficient_data` позволяет вернуть конкретные уточнения по содержанию. Запрос отправляется в локальный `POST /api/chat`. [Документация API Ollama](https://docs.ollama.com/api/chat)
3. Программа проверяет заголовок до 70 символов, описание от 800 до 1200 символов, от 3 до 5 разных поисковых запросов и наличие блока для менеджера. Цифры в генерируемом тексте допустимы внутри названия товара или производителя. Если черновик не прошёл проверку, программа отправляет замечания модели и делает один повторный запрос.
4. Для принятого ответа программа собирает Markdown. Технические значения она подставляет из `specs`. Причины отказа в сохранении карточки попадают в `data/to_fix.json`.

## Ограничения и возможные улучшения

- Программа проверяет формат ответа и подставляет характеристики из JSON. Свободный текст требует сверки с источником. В черновиках модель может расширить заявленные возможности прибора, например сделать вывод о качестве теплоизоляции на основе сценария замеров рядом с окном.
- Выгрузка рассчитана на структуру страниц исходного каталога. Для новых ID нужен доступ к страницам товаров. Для запуска по готовым JSON достаточно локального Ollama и загруженной модели.
- При коротком исходном описании модель может вернуть уточнение или не уложиться в требуемый объём. Такой ID попадает в отчёт для проверки данных.
